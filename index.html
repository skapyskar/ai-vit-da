Depth-first exploration, with a deliberate stopping point.

How it works

DLS follows one branch of the state-space tree until it finds the goal or reaches a chosen depth limit ℓ. It then backtracks and tries the next branch. Every state is a configuration of eight numbered tiles and one blank; a successor moves the blank one cell up, right, down, or left.

  1. Start at depth 0 with the initial state.
  2. Test for the goal first, including at the depth limit.
  3. If the bound is reached, report a cutoff for that branch.
  4. Otherwise, generate legal successors and exclude ancestors on the active path.
  5. Explore successors depth-first, then backtrack. Report a solution, cutoff, or exhausted search.

Why a cutoff matters

A cutoff means the limit prevented further exploration. It does not mean the puzzle is unsolvable. An inversion-parity check rejects unreachable initial/goal pairs before search. If the visit budget is reached, the result is “Resource limit reached,” which is also inconclusive.

Advantages & limitations

The bound prevents unbounded descent, and a depth-first frontier needs little search memory. DLS is useful when a reasonable solution-depth bound is known. However, a small bound can miss the goal, a large bound can do exponential work, and the first solution need not be the shortest.

Completeness & optimality

DLS is complete within the chosen bound for finite branching when permitted to finish: if a solution exists at depth ≤ ℓ, it can find one. It is not complete for goals beyond that bound, and it is not optimal with unit move costs. This app’s safety budget can interrupt an otherwise complete bounded run.

The core idea

DLS(state, remaining, path):
  if state == goal:
    return solution(path)
  if remaining == 0:
    return CUTOFF

  cutoff = false
  for child in successors(state):
    if child not in path:
      result = DLS(child,
        remaining - 1, path + child)
      if result is solution:
        return result
      cutoff |= result == CUTOFF

  return CUTOFF if cutoff
         else FAILURE

The 8-puzzle problem

Arrange eight numbered tiles on a 3 × 3 board to match a goal configuration. The empty cell can swap with one orthogonally adjacent tile. The puzzle demonstrates state-space search: each board is a state, legal moves form edges, and a solution is a path to the goal.

About this assignment

Built by Aayush Dwivedi, registration 24BCT0058, for the Artificial Intelligence course. The allocation table assigns algorithm 3: Depth Limited Search.

The brief explicitly asks students to implement only their assigned algorithm. This project therefore uses DLS throughout. The comparison experiment measures different limits, and heuristic controls are omitted because DLS uses no heuristic.

Use the lab

  1. Choose an example, enter your own initial and goal states, or generate a solvable puzzle.
  2. Set a depth limit and run. Pause to inspect the current node, parent, successors, and frontier.
  3. Step backward or forward through retained search events. Change playback speed at any point.
  4. After success, play the solution moves on the large board or select any state in the solution path.
  5. Compare limits on the same puzzle. Download a run as JSON to keep its results.

Built with

HTML5, CSS3, JavaScript ES modules, and self-hosted Bootstrap 5.3.8. The search is implemented from scratch. No backend, account, API key, or search library is needed.
