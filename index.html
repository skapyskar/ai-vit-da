Depth Limited Search

DLS is depth-first search with a fixed depth limit. It follows a branch until the goal or the limit is reached, then backtracks.

Procedure

  1. Start with the initial state at depth 0.
  2. Check whether the current state is the goal.
  3. If the depth limit is reached, return a cutoff.
  4. Generate legal moves in the order Up, Right, Down, Left.
  5. Skip states already on the current path. Search each remaining branch, backtracking when needed.

Pseudocode

DLS(state, remaining, path):
  if state == goal: return path
  if remaining == 0: return CUTOFF

  cutoff = false
  for child in successors(state):
    if child not in path:
      result = DLS(child, remaining - 1, path + child)
      if result is a solution: return result
      cutoff = cutoff or result == CUTOFF

  return CUTOFF if cutoff else FAILURE

Properties

Time complexity O(bℓ)
Space complexity O(bℓ) for the search. Saved visualization steps use extra storage.
Completeness Finds a solution within the limit if allowed to finish. A solution beyond the limit is missed.
Optimality Not optimal. The first solution may be longer than necessary.
Heuristic None. DLS is an uninformed search.

b is the branching factor (at most 4). ℓ is the depth limit.

Advantages

Uses a small frontier and avoids searching below a chosen depth. Useful when a reasonable depth bound is known.

Limitations

A low limit can miss the solution. A high limit can require many visits. A cutoff means more depth may be needed; it does not mean the puzzle is unsolvable.

Implementation notes

The solver checks inversion parity before searching. It stops after 50,000 visits and retains the latest 2,000 search steps. The closed list is a display of expanded visits; cycle prevention uses the current path.
